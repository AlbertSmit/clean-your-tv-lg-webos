# Final isolated TV update check

Scope is frozen: validate permission setup, an update with preserved data, and rollback. This is not a public installation guide. Production Home, Helper, startup and system profiles must remain unchanged.

## Prepared locally

Build with `ARES_PACKAGE=/path/to/ares-package python3 scripts/build-update-lab.py`. The output is `dist/update-lab/`:

- `com.cleanyourtv.updatetest_1.2.0_all.ipk`: one test tile.
- `com.cleanyourtv.updatetest_1.2.1_all.ipk`: empty inventory requiring preserved data.
- `com.cleanyourtv.updaterlab_0.1.0_all.ipk`: independent updater and recovery UI.
- `http/`, setup scripts and `SHA256SUMS`.

Each build generates an ephemeral signing key. Only its public key is packaged. Metadata and package hashes are signed together. Do not mix files from different builds. These artifacts never enter the public release channel.

Lab substitutions: loopback HTTP for package delivery, packaged signed metadata instead of GitHub, fixed helper compatibility version, fake renewal results and fake scheduling. There are no LG requests, token reads, real background activities or Home interception. Production compatibility checks and scheduling still require their own existing tests; this lab does not prove them.

## Single TV session

1. Confirm the TV is available. Record production package hashes and the running helper PID. Save any previous lab data locally; use a clean lab baseline rather than silently adopting a previous run's state.
2. Transfer only the lab bundle to a temporary TV directory. Install the baseline target 1.2.0 and Updater Lab; verify terminal installer success and installed IDs. Do not install the production updater.
3. From the transferred bundle, review `node scripts/update-permissions.cjs plan lab`. Apply with `node scripts/update-permissions.cjs apply lab`. Only `/var/luna-service2-dev` is used for this session.
4. Start Python's HTTP server in the bundle's `http/` directory, port 18999, bound to **127.0.0.1**. Record its PID. No Mac firewall changes or external HTTP exposure are needed.
5. Open Update Test. Check Software updates. This must show the installed 1.2.0 and signed candidate 1.2.1. A permission error stops the test; do not broaden grants to `all` or edit production permission files.
6. Enable the lab Beta fixture, change tile order if possible, and run Update Home → Confirm update. Verify the journal reaches `awaiting-launch`, reopen Update Test and verify 1.2.1, preserved tile/icon/settings, restored enabled preference and `complete`. No manual Beta toggle should be necessary during installation.
7. Open Updater Lab → restore the previous version. Verify 1.2.0, the same inventory and renewal preference, and terminal `rolled-back`. A timeout/unknown outcome stays blocked; do not repeatedly press install.
8. Remove the scoped grants with `node scripts/update-permissions.cjs remove lab`; verify the bus no longer grants the cross-package calls. Stop the recorded loopback server. Return to production Home, compare hashes/PID and ask for one short Home/navigation check.

Capture the response and journal for each step. If an actual defect appears, fix that defect and repeat only its affected path. Do not add unrelated experiments.

## Permission setup behavior

The CLI requires Linux root for apply/remove, accepts only the two fixed LS2 roots, and requires an explicit lab/production selection. The laboratory plan never grants access to production Home or Helper. A dedicated receipt records the exact generated bytes before changes. Existing filenames are rejected; symlink parents/targets and changed managed files are rejected. The manifest is written last and removed first. Temporary writes use exclusive creation, fsync and a no-overwrite hard link. A directory lock prevents overlapping invocations.

Refresh is a bounded `ls-control scan-services`, following the locally inspected Homebrew setup implementation. A refresh failure is reported and retains the receipt so removal can be retried. A lock left by a killed process requires operator inspection before removal; it is never automatically assumed stale. A partially written staging file is also a stop condition rather than permission to erase unknown content.

Acceptance of the independent manifest, merging with existing grants, and refresh/unload behavior are **not yet verified on TV**. The installer does not establish these facts merely by writing files. Production use and a release remain blocked until the lab session passes.
